## 1. 產品願景、設計支柱與非目標

一句話：在一個會自行運作的像素世界中，玩家以有限公共權力引導聚落，觀察居民、家庭、產業、環境與歷史共同演變。

-   **可見**：重要狀態改變必有地圖、動畫、人物或事件回饋，不只數值跳動。

-   **可理解**：重大變化可追溯條件、行動、成本、受影響者及結果。

-   **自主**：NPC 具持續目標與行為慣性，不靠亂數假裝自由。

-   **有取捨**：政策與建設都有機會成本，沒有唯一最佳路線。

-   **可恢復**：災害有預警、可回應。

-   **低負擔**：主畫面最多 3 個摘要狀態，詳細帳務藏於次級面板。

**設計價值**：沒有唯一的「好結局」分數；介面同時顯示平均與分配（例如貧富差距），效率與公平的取捨交給玩家；偏袒等道德選擇只呈現後果，不由遊戲評判；任何政治或經濟路線都有代價與適用條件。

**學理運用**：經濟學是底層引擎，系統化實作（第 7
章）。心理學、社會學、人類學、政治學、歷史學只採用同時通過三項檢驗的機制：產生玩家可感受的取捨、能以整數規則計算、玩家看得懂結果。每個借用的理論都以
ADR 記錄來源與簡化方式。

**核心敘事鉤子**：玩家是村中領袖，也是有家庭與壽命的居民。缺糧、婚喪與傳承都發生在玩家自己的家族身上，世代交替成為玩法本身（見
2.0）。

**非目標**：即時多人、LLM 驅動
NPC、戰爭外交、無限地圖、銀行信用創造、背景或離線模擬。

## 2. 玩家權限與遊玩循環

玩家的主要動詞是「回應居民提案」，其次是公共建設與財政；私人生活、投資與就業由
NPC 自主決定。主循環為：觀察 → 比較方案 → 引導或放任 → NPC 回應 →
因果回顧。每項主要危機至少有兩條有效介入路徑，以及一條「不干預」後的合理發展。

### 2.0 玩家角色：村中領袖

玩家扮演聚落領袖，同時是一位有家庭、帳戶、技能、關係與壽命的居民；公共權力來自職位，而非上帝視角。玩家永遠扮演同一個家族。

-   **日常自主**：玩家角色的吃飯、工作、移動仍由 AI
    執行，避免照護負擔。玩家只決定重大個人選擇：職業、本人婚姻同意、搬遷、家庭投資、指定繼承人候選；子女的職業與婚姻仍由子女自主。

-   **公私分離**：家庭帳戶與公共帳戶分開，帳本禁止挪用公款。偏袒（例如把道路修到自家田邊）是合法的，但居民會察覺並降低支持度。

-   **支持度（0--100，每季計算）**：先算每位成年居民的滿意度，再依職業匯總為農戶、工匠、商人等利益群體，總支持度為各群體的人數加權平均。因子為需求滿足、稅負、提案回應、偏袒感知、危機處理；滿意度採損失趨避與享樂適應（見
    5.5）。權重待校準。

-   **支持度效果**：≥ 60 正常施政；40--59 時新政策生效延後一季；連續兩季
    \< 30 觸發改選。

-   **改選**：由支持度最高的其他居民與玩家競選。落選時玩家角色成為一般村民，仍可做個人選擇並累積聲望，下次年度改選可再參選；期間由
    AI 代理領袖依 2.0.1
    的限縮規則施政。這是溫和的失敗狀態，不會結束遊戲。

-   **繼任**：領袖死亡或卸任時，若支持度 ≥
    50，由玩家指定的成年家族成員繼任；否則舉行改選。玩家改為控制家族新家長，家族斷絕時可選擇另一個家族或封存聚落紀錄。

-   **自動降速**：玩家家族的出生、成年、婚姻、重病、死亡與改選事件，一律自動降回正常速度。

#### 2.0.1 補充規則

-   **開局**：從 3 個家族中選一個，所選家族家長即為首任領袖，初始支持度
    60。範例：農耕世家（農業技能高、與農戶關係深）、工匠家族（工藝技能、持有工具）、商旅家族（商業技能、現金較多、與貿易節點有往來）。

-   **領袖俸給與公務**：領袖可兼任一般工作，但每週固定 1 日處理公務，這
    1
    日沒有生產。俸給每月由公共帳戶支付，金額由「領袖俸給」政策設定；高於基準的部分會降低支持度。

-   **偏袒判定**：每季以連續 4 季的累計值計算「偏袒比 =
    玩家家族及親屬的公共受益占比 ÷
    其人口占比」；累計公共支出低於門檻時不判定，避免小村單筆建設被誤判。受益以建設服務範圍內的住宅與農田、以及補助領受者判定。偏袒比
    \> 1.5 開始扣支持度，越高扣越多。

-   **重病與死亡**：領袖重病時先觸發預警並自動降速，提示指定繼承人；從重病到死亡至少
    30 遊戲日。V1 不設會讓領袖立即死亡的事件。

-   **AI
    代理領袖（玩家落選期間）**：只維持現行政策與稅率，不主動興建。提案依規則審核：成本
    ≤ 公共資金 20% 且證據分數達門檻即核准，否則延後。

以上數值皆為待校準（見第 18 章）。

### 2.3 居民提案（V1 核心）

觸發例：道路繞行成本高、住房缺口 \>15%、存糧撐不到下次收成＋10
日、診療覆蓋不足。提案欄位：proposer_id、target、evidence、cost、expected_effects、expiry、status。玩家可核准、延後或拒絕；拒絕不封鎖其他自主路徑，但會降低提案人家庭對領袖的信任，核准則提高；提案因此也是人情取捨。每季最多
3 件高優先提案。

### 2.4 決策預覽與因果回顧

所有政策與提案顯示：原因、受影響群體、公共成本、所需物資、最早生效日、短期預估、長期風險。預估為條件推演，不保證
NPC 配合。歷史回顧需提供 command_id → 建設／政策事件 → NPC 行為 →
經濟變化的可追溯鏈。

## 3. 時間、曆法與模擬排程

曆法已鎖定：每年 360 日、每季 90 日、每月 30 日、每週 6 日（每季 15
週、每年 60 週），週、月、季邊界永遠對齊；每週第 6
日為休息日。所有公式只能使用此曆法。

  -------------------------------------------------------------------------
  速度        步進               1 季           1 年         10 年
  ----------- ------------------ -------------- ------------ --------------
  正常        3 秒／日           4.5 分         18 分        3 小時

  快速        2 日／秒           45 秒          3 分         30 分

  極速        5 日／秒           18 秒          72 秒        12 分
  -------------------------------------------------------------------------

速度只改變每秒步進次數，不改變規則或機率。

**世代節奏**：一代（約 25 年）在正常速度下約需 7.5
小時，問題在於太慢而非太快。對策是讓快速模式成為長期遊玩的預設，並在被追蹤人物的婚育、成年、死亡或重大事件發生時自動降回正常速度。3
秒／日仍為待校準值。

### 3.1 每日固定處理順序

1.  接收並排序玩家命令，校驗預算與權限。

2.  環境與日曆更新，到期事件生效。

3.  每日需求與緊急行為，預約資源與工作。

4.  移動進度、生產與施工結算。

5.  消費與帳務記錄（每日彙總，見 7.4）。

6.  週期觸發：每週市場與 NPC
    計畫；每月工資與遷徙；每季收成與政策；每年年齡與快照。

7.  事件與歷史摘要、渲染差量；不變量檢查僅在 debug／CI 模式每日執行。

出生、成年與死亡以遊戲年計算，V1 不強制快速繁殖。

## 4. 地圖、尋路與細節層級

V1 只模擬一個核心聚落：地圖 96×96 格，初期可建區 48×48，以 16×16
區塊管理；地形 tile 為 16×16 px。

-   **地形欄位**：tile_id、height_class、soil、forest、water、buildable、walk_cost。

-   **建築佔地**：footprint 與出入口格；放置時驗證可達性、坡度與碰撞。

-   **尋路**：A\*，同分路徑以格座標 ID
    決定性排序（tie-break）；道路圖分層並批次快取，道路或橋梁變動時使相關快取失效；不逐幀為所有
    NPC 尋路。

-   **細節層級（LOD）**：只有單一權威世界狀態與單一日步進。縮放只改變渲染細節（逐人動畫
    ↔ 群集圖示），不是兩套模擬，因此不存在「近遠景切換」的守恆問題。

-   **區域特色**：農業、森林、礦區、河港由地形資源與交通成本自然形成，不使用固定升級樹。

地圖外的世界以 2 個「貿易節點」表示（見 7.5），V1 不模擬節點內的 NPC。

### 5.2 三段式決策

1.  **硬條件過濾**：生存急迫性、可達性、職缺、現金、材料、健康。

2.  **效用評分**：U(a) = Σ wᵢ·fᵢ(a) − 成本項。各因子 fᵢ 以整數 0--1000
    表示（定點數），權重表放在 packages/content 的
    JSON，依行動類型定義。求職範例：收入 300、家庭 200、技能適配
    200、穩定 150、偏好 150，再扣通勤、轉職成本與風險。

3.  **慣性**：新行動效用須比現行計畫高 120（即
    0.12）且已過冷卻期；緊急生存行動可直接覆蓋。

每次評分輸出 debug_reason 供測試，不在玩家畫面顯示原始權重。狀態機：Idle
→ Evaluate → Plan → Reserve → Travel → Execute → Settle →
Cooldown；失敗進入 Replan 或 Fallback。

玩家角色是 controller = player 的 NPC：日常仍走同一套三段式決策，只有
2.0 列出的重大個人選擇改由玩家命令決定。改選時，候選人與投票由 AI
居民依支持度因子自主決定。

### 5.3 家庭、關係與經歷

-   家庭每週規劃採購與儲蓄，每月評估住宅、教育與遷徙；家庭帳戶與個人收入的移轉必須記帳。

-   關係只做親屬、朋友、雇用、合作四類，且必須實際影響求助、留任、交易與繼承。

-   經歷例：欠薪 → 對雇主信任下降 → 尋找新工作；饑荒 →
    提高家庭安全存糧。記憶有強度與衰減，不遺傳性格；後代只透過資產、教育、技能、環境與關係傳承。

-   婚育遵守成年、雙方意願、家庭資源與關係條件；玩家不得強制配對。

-   死亡須原子化處理：資產繼承、職缺釋出、家庭關係、歷史墓碑。

### 5.4 必要行為測試

-   連續缺糧會尋找糧食或求助。

-   收入下降可能轉職，但不每日震盪。

-   工作地不可達時取消任務。

-   企業欠薪後員工留任意願下降。

-   NPC 死亡後繼承與職缺正確結算。

### 5.5 心理與社會機制

-   **損失趨避（心理學）**：滿意度評價中，損失的權重為收益的 2
    倍；取消補助或加稅造成的不滿，大於當初給予時的滿意。

-   **享樂適應（心理學）**：滿意度每季向個人基準回歸
    25%，改善必須持續才有感。

-   **利益群體（政治學）**：成年居民依主要職業歸入農戶、工匠、商人，無業者另計；群體偏好用於提案生成與支持度匯總。

-   **社會資本（社會學）**：信任決定求助與合作對象的順序；信任高的網絡互助成本較低。

-   **互惠與人情債（人類學）**：借糧、幫工記為非貨幣人情債，獨立於貨幣帳本；受惠者優先回報，長期未回報會降低信任。

-   **創新擴散（社會學）**：輪作、家具消費、新工作等新做法，每週採用機率
    = 基礎值 + 已採用親友比例 × 擴散係數，不會全村同時採用。

-   **人口動態（歷史人口學）**：出生率隨人均存糧與住房餘裕上升；聚落吸引力（糧價、工資、住房、支持度）高時有家庭從貿易節點移入，低時有家庭移出。

## 6. 建築、施工與公共勞動

公共工程由公共帳戶以工資雇用 NPC 施工；NPC
依效用自行決定是否接工，因此公共建設會與私人產業競爭勞力，這是刻意設計的取捨。

冬季是農閒期：農業邊際產值為零，勞力自然流向伐木與公共工程，形成「春夏秋耕作、冬季建設」的年度節奏。大型工程排在冬季最容易招到人，也最不影響糧食。

### 6.1 生命週期

藍圖 → 預約材料 → 施工 → 啟用 → 維護 → 擴建／轉用 →
老化／修復／拆除。每次狀態變化都要有資源扣除、施工人日與視覺變化，不可瞬間完成。

### 6.2 公共工程流程

1.  玩家下達命令：驗證可達性、預算與材料，確認前不扣款。

2.  材料從公共庫存預約；不足時工程進入「等待材料」。

3.  公共帳戶發布施工職缺與日薪；工資每日從公共帳戶轉入工人帳戶。

4.  累計人日達標後啟用，記錄 BuildingCompleted 事件。

### 6.3 住宅取得（V1 簡化）

V1
不做住宅買賣市場。住宅分為公共住宅（玩家興建、家庭繳租）與家庭自建（家庭出材料與人日）；空屋依「需求急迫度
→ 等候時間 →
household_id」的決定性順序分配。普通物品採批次庫存，只有重要收藏品保留個別履歷。

## 7. 經濟系統（以經濟學原理設計）

經濟採代理人基礎模型：每個家庭與企業依「多做一單位值不值得」的邊際比較做局部決策，價格與工資依超額需求逐週調整；不求解全域均衡，均衡由互動中浮現。所有曲線以整數查表實作，數值皆為待校準。

### 7.1 商品與家庭需求層級（恩格爾法則）

V1
商品：糧食、木材（兼燃料）、石材、工具、家具。貨幣是帳戶餘額，最小單位為整數「文」。

家庭每週依下列順序分配預算，前一層滿足後才進入下一層；收入越高，支出越往後層擴散：

1.  糧食：每人每日 1。

2.  燃料：冬季每戶每日 1 木材。

3.  住房：公共住宅租金或自建維護。

4.  工具：每名工作者每季耗損 1。

5.  家具：耐久消費品，提升舒適；每件每年折舊，需汰換。

每層有飽和點，超過後邊際效用為零，避免無限囤積。

### 7.3 勞動市場

-   **雇用規則**：企業與農戶在「下一名工人的邊際產值 ≥
    工資」時雇人；連續 2 週低於工資才解雇，避免震盪。

-   **工資調整**：各部門工資每週依勞動超額需求調整，單週上限
    ±5%，下限為最低生活費；低於下限造成的失業由救濟承接。

-   **勞動供給**：家庭需求層級已滿足且儲蓄高於目標時，成員可選擇休閒日（提升心情），因此「沒人雇」與「不想做」會被分開統計，只有前者算失業。

-   **農閒**：冬季農業邊際產值為零，農戶勞力自然流向伐木與公共工程。

### 7.4 價格、儲存與套利

每週流程：收集賣單與買單 → 依可達性、現金、庫存篩選 → 固定順序撮合 →
原子化轉移商品與貨幣 → 稅入公共帳戶。

-   價格：P_next = P × (1 + 0.10 × (D − S) ／ max(D, S, 1))，再限制在
    0.5--2.5 × P_base；單週變動最多 ±10%，不再另設上限。

-   需求每週重新計算；未成交需求只做標記，不累加到下週，避免價格被重複計算的需求推到上限。

-   儲存：糧食每月損耗 1%，受倉庫容量限制。

-   套利：預期價格 = 過去 4
    個同季的移動平均（適應性預期）。家庭與商人在價格低於預期時多買存放、高於預期時出售，自然平滑秋收後的低價與春荒前的高價。

### 7.5 貨幣與財政

-   **封閉帳本**：貨幣只因初始配置、貿易順差或逆差、鑄幣三種明示事件改變。

-   **鑄幣政策**：領袖決定每季發行量並撥入公共帳戶。人口與產量成長而貨幣不增會導致長期通縮，發行過多則物價上漲；兩者都由市場自然呈現，不另寫規則。

-   **稅收**：收成稅（以實物糧食入公共存糧，0--20%）、商業稅（成交額比例）、公共住宅租金。稅率提高會降低稅後邊際報酬，使生產與交易減少，稅收不一定增加。

-   **救濟**：家庭存糧低於 7 日時，以公共存糧救濟，並記錄經歷標籤。

## 8. 政策、環境與事件

事件頻率改以遊戲年計：重大事件每年最多 1 件、中等事件每季最多 2
件，符合「輕鬆觀察」定位（舊規則在正常速度下約每 5 分鐘一件重大事件）。

### 8.1 政策（V1）

住宅補助、農業補助、收成稅率、商業稅率、鑄幣發行量、保育區、道路優先、領袖俸給、教育與醫療預算（後兩者
B2
起）。每次變更顯示財政負擔、受益群體、可能副作用與生效季；政策不保證正向效果。

### 8.2 環境

-   **森林**：邏輯斯成長 ΔF = r × F × (1 − F / K)，r 初始 2%／季，K
    為該格承載上限；另加每季 0.2% K
    的自然更新，並提供公共「植林」行動，避免砍光後無法恢復。

-   **肥力**：0--100；每次收成 −2、冬季 +4、刻意休耕一季 +6，上限
    100。年淨變化約 −2，需每隔數年輪作；產量品質係數 = 0.5 + 0.5 ×
    肥力／100。

-   **水源與季節**：影響季節係數；污染延後至 V2。

需以 50 年模擬測試資源不會必然耗盡。

### 8.3 事件模板

V1 至少 10
種模板，欄位：trigger、preconditions、weight、effects、cooldown、recovery、visibility。事件必須可預警、可追溯、有恢復途徑。重大事件觸發時，快速與極速模式自動降回正常速度並提示玩家。

## 9. 歷史與傳承

歷史只為「能被玩家看見、且會影響未來」的事件保留因果鏈；日常事件只做彙總。

-   **事件欄位**：event_id、tick、type、actor_ids、place_id、cause_event_ids、state_deltas、summary、importance、visibility。

-   **分類**：系統事件、人物事件、外部事件；importance 決定保留期限（見
    12.2）。

-   **歷史影響規則**：曾缺糧的家庭提高安全存糧；長期經營工坊的家族累積技能傳承；橋梁毀損改變交通偏好。每條影響有範圍、權重與衰減期限。

-   **聚落分化**：依資源、地形、職業與產業比例逐漸形成農業、森林、工匠、商業等導向，可混合、可轉型，不使用固定升級樹；耐玩性來自地形、家庭財富、技能與歷史，而非純隨機災難。

-   **玩家可見**：人物傳記（玩家家族優先）、家族世系、歷任領袖與任期、企業沿革、聚落年表、每
    5 年地圖對照；重要事件可點回原因與相關人物。

-   **敘事模板**：重要事件以模板生成自然語言摘要（例：「因秋收不足，某家族長子前往河港謀生」），而不是只顯示數值變化。

長期動態：

-   **馬爾薩斯循環**：糧食盈餘 → 出生與移入增加 → 人均糧食下降 →
    成長放緩或移出，形成長期波動，而不是無限成長。

-   **路徑依賴**：早期道路與市集位置會提高周邊建設與移入的吸引力，聚落形狀因此延續早期決策。

命令含 command_id、expected_world_version、issued_tick、payload，回覆
accepted／rejected 與
reason。核心命令：BuildRoad、PlaceBuilding、ZoneLand、SetPolicy、FundProject、RespondProposal、FollowEntity、SetPersonalChoice、NominateHeir、SetSpeed、Pause、Save、Load。事件：BuildingStarted、BuildingCompleted、JobChanged、TradeSettled、PolicyApplied、BirthRecorded、DeathRecorded、MigrationCompleted、LeaderChanged、ElectionHeld、EventTriggered。

### 11.3 決定性規則

固定 seed＋PRNG 狀態＋命令序列＋邏輯版本必須重現相同狀態 hash。

-   世界狀態禁止使用 Math.random、Date.now 與 performance.now。

-   模擬核心內貨幣、價格、效用、需求一律使用整數或定點數。

-   禁止在影響狀態的計算中使用 Math.exp、Math.pow、Math.sin、Math.log
    等可能因 JS 引擎而異的函式；需要曲線時改用查表。

-   所有集合迭代在影響狀態前依 ID 排序；同 tick 多命令依 (issued_tick,
    command_id) 排序；A\* 同分以格座標決勝。

-   以 ESLint 自訂規則在 packages/sim 內禁止上述 API，CI 自動攔截。

## 12. 存檔與資料保留

關閉 App
即暫停世界，不做離線追趕；重新開啟時從存檔原狀繼續。這移除了整套追趕、預覽與「離線不結算災害」規則。

### 12.1 存檔格式

IndexedDB 版本化 schema；存檔含
world_version、schema_version、sim_version、seed、prng_state、tick、entity_state、ledger、event_log、checksum。寫入暫存
→ 驗證 → 更新有效指標；保留最近 3 個恢復點；支援匯出／匯入。每個 schema
版本都要附遷移函式與測試。自動存檔於每季結束與 App 進入背景時觸發。

### 12.2 資料保留

  -----------------------------------------------------------------------
  資料                        保留方式
  --------------------------- -------------------------------------------
  帳本明細                    近 2 遊戲年；更早壓縮為每帳戶年度摘要

  日常事件                    每年彙總為年度摘要後刪除明細

## 14. 驗收情境

所有情境都以 tools/headless 在 Node 無畫面執行，並納入
CI；每次合併前至少跑「正常成長 10 年」與「存檔回放」。

  --------------------------------------------------------------------------
  情境                必要檢查
  ------------------- ------------------------------------------------------
  正常成長 10 年      無負庫存、重複人物、無限財富、不可達建築

  冬季存糧不足        秋末有預警；家庭調整消費或求助；存在恢復途徑

  連續歉收            至少兩條有效介入路徑與一條不干預路徑都不導致必然滅村

  工坊虧損            企業可節流、停工或退出；工人重新求職

  道路中斷            尋路快取失效、在途工作重排、價格反應合理

  人口老化            出生、死亡、繼承、職缺與家戶資產一致

  貿易在途            貨物不同時存在兩地；運抵後守恆

  存檔回放            同 seed＋命令序列＋版本 → 相同狀態 hash

  速度一致性          不同速度推進到同 tick → 相同 hash

  高速 50／100 年     無死循環、記憶體無無界增長、事件頻率受控、存檔 \< 20MB
  --------------------------------------------------------------------------

領袖相關情境：

-   **偏袒與支持度**：只為玩家家族修路，支持度下降且原因可在回顧中追溯。

-   **改選落選**：玩家轉為一般村民，AI
    領袖接手，帳務與命令權限正確切換。

-   **繼任**：領袖死亡時繼任或改選結果正確，玩家控制權轉移到家族新家長，存讀後
    hash 一致。

經濟與社會情境：

-   **勞動市場**：失業增加時工資下降、雇用回升；非自願失業不長期高於
    10%。

-   **季節價格**：秋收後糧價下跌、春荒前上漲；儲存套利使波幅逐年縮小。

-   **貨幣**：零鑄幣下人口成長造成溫和通縮，過量鑄幣造成通膨，物價變化可追溯到政策。

-   **損失趨避**：取消補助後支持度的下降幅度，大於當初給予時的上升幅度。

-   **創新擴散**：新做法沿人際網絡逐步擴散，不會同時採用。

-   **人口循環**：糧食盈餘帶來人口成長，逼近上限後放緩，不爆炸也不滅絕。

**第一個整合驗收**：24 人聚落自主運作 3
遊戲年，居民能工作購糧、企業能調整生產、家庭能改變消費、道路建設造成可解釋的行為變化、冬季缺糧時有恢復路徑、歷史可回溯，且無負庫存、貨幣憑空產生或重複人物。

## 16. Claude Code 協作規則

開發者負責規格、驗收與審查，Claude Code
負責在明確邊界內實作；測試是兩者之間的合約，因此測試的意圖由開發者定義，Claude
Code 不得為了讓測試通過而修改它。

### 16.1 Repo 內的固定文件

-   **CLAUDE.md**：專案目標、指令（test、lint、headless）、模組邊界、決定性規則、禁止事項；控制在
    200 行內，細節以連結指向 docs。

-   **docs/spec/**：本 GDD
    依章節拆成小檔，任務只載入相關章節，避免上下文過長。

-   **docs/adr/**：每個架構決策一份 ADR，Claude Code
    在重新提出已否決方案前須先讀。

-   **docs/tasks/**：任務卡。

### 16.2 任務卡（每張必填）

目標、前置依賴、允許修改路徑、資料契約、失敗情境、測試案例、效能預算、人工驗收、回滾方式。一張卡應能在一次工作階段內完成，修改不超過約
300 行；不得一次要求完成整個社會或經濟系統。

### 16.3 工作流程

1.  先讀相關規格與 ADR，列出將修改的檔案。

2.  先寫或更新測試，由開發者確認測試意圖。

3.  實作最小切片並跑 CI 與 headless 情境。

4.  開發者審查 diff 與人工驗收後才合併；必要時記錄 ADR。

### 16.4 護欄

-   不變量測試、決定性測試與 schema
    檔列為受保護路徑：修改需在任務卡中明確授權，並在 PR 說明理由。

-   以 hooks 在每次提交前自動執行 lint、typecheck 與單元測試。

-   禁止未經核准的跨模組大改、新增依賴或改動 packages/schema。

-   所有「待校準」數值放在 packages/content，Claude Code
    不得自行在程式中寫死新數值。

-   每個階段結束時，請 Claude Code
    依本文件逐條比對實作並列出偏差，作為獨立審查。
