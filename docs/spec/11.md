## 11. 技術架構與決定性

模擬核心是不依賴瀏覽器的純 TypeScript 套件，可在 Node
無畫面執行；這讓平衡調整、長期壓測與 Claude Code
的自動測試都不需要啟動遊戲畫面。

### 11.1 Repo 結構

-   apps/web：Phaser 地圖＋DOM 面板

-   packages/sim：純模擬核心（禁止 import DOM、Phaser）

-   packages/schema：Zod 型別與資料契約

-   packages/content：JSON 內容與權重表

-   packages/persistence：存檔與遷移

-   tools/headless：Node 批次模擬與平衡報表

-   tests：單元、整合、長期

-   docs：GDD、ADR、任務卡

### 11.2 執行緒與命令

主執行緒只處理輸入、畫面與展示狀態；Worker
接收序列化命令，輸出狀態差量與事件，渲染不得改寫模擬狀態。NPC 熱資料以
SoA（TypedArray）儲存，差量以 transferable 傳遞。

命令含 command_id、expected_world_version、issued_tick、payload，回覆
accepted／rejected 與
reason。核心命令：BuildRoad、PlaceBuilding、ZoneLand、SetPolicy、FundProject、RespondProposal、FollowEntity、SetPersonalChoice、NominateHeir、SetSpeed、Pause、Save、Load。事件：BuildingStarted、BuildingCompleted、JobChanged、TradeSettled、PolicyApplied、BirthRecorded、DeathRecorded、MigrationCompleted、LeaderChanged、ElectionHeld、EventTriggered。

### 11.3 決定性規則

固定 seed＋PRNG 狀態＋命令序列＋邏輯版本必須重現相同狀態 hash。

-   世界狀態禁止使用 Math.random、Date.now 與 performance.now。

-   模擬核心內貨幣、價格、效用、需求一律使用整數或定點數。

-   禁止在影響狀態的計算中使用 Math.exp、Math.pow、Math.sin、Math.log
    等可能因 JS 引擎而異的函式；需要曲線時改用查表。

-   所有集合迭代在影響狀態前依 ID 排序；同 tick 多命令依 (issued_tick,
    command_id) 排序；A\* 同分以格座標決勝。

-   以 ESLint 自訂規則在 packages/sim 內禁止上述 API，CI 自動攔截。
